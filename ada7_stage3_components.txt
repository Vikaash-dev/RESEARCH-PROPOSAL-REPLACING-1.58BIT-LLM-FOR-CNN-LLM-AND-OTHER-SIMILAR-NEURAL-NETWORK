3.2  DATA FLOW DIAGRAM
────────────────────────

Training Flow (ResiBit):
  Input X
    ├──→ Conv(X; quantize_ternary_ste(w_a)) → y_a  [Expert A]
    ├──→ Conv(X; quantize_ternary_ste(w_b)) → y_b  [Expert B]
    └──→ Conv(X; quantize_int8_per_channel(w_r)) → y_r  [Highway]
          │
          └──→ Group-Mix: α_a·y_a + α_b·y_b + α_r·y_r
                  │
                  └──→ BatchNorm → SiLU → Output Y

Deployment Flow (Base-5):
  Input X
    ├──→ Conv(X; WB5)    [Fused Base-5, shift-and-add]
    └──→ Conv(X; WR_i8)  [INT8 residual, standard MAC]
          │
          └──→ α_merged·y_b5 + α_r·y_r → BN → SiLU → Y


3.3  TECHNOLOGY SELECTION
──────────────────────────

Component: Deep Learning Framework
  Primary: PyTorch 2.3+ (exact match with paper implementations)
  Alternative: JAX/Flax (migration complexity: HIGH)
  Justification: Papers provide PyTorch code listings directly

Component: Quantization Backend
  Primary: Custom STE-based (implemented in quantization.py)
  Alternative: PyTorch quantization.quantize_dynamic (not flexible enough)
  Justification: Absmean ternary quantization is not in standard library

Component: Object Detection Framework
  Primary: Ultralytics YOLO26 (paper's target)
  Alternative: mmdetection, Detectron2
  Justification: YOLO26's DFL-free, NMS-free design is integral to approach

Component: Testing Framework
  Primary: pytest 9.0.2 (existing in repo)
  Alternative: unittest
  Justification: Already established with 146 passing tests

Component: Hardware Deployment
  Primary: Custom CUDA PSLUC kernel (for GPU)
  Alternative: FPGA HDL (for ASIC)
  Justification: Papers describe both pathways
