    - ResiBit-YOLO with dual-expert ternary + INT8 highway
    - COCO training and evaluation

  v1.1 (Post-Launch, Month 2-3):
    - Learned STE (adaptive step size)

  v1.2 (Month 4-6):
    - ARM NEON ternary inference kernels (C/C++)
    - ncnn integration for mobile deployment
    - Multi-scale training support
    - Model zoo: nano, small, medium variants

  v2.0 (Month 7-12):
    - Extension to segmentation (ternary YOLO-seg)
    - Extension to pose estimation (ternary YOLO-pose)
    - Dynamic MoE routing (replacing SCS)
    - Multi-GPU distributed QAT

  v3.0 (Year 2):
    - Ternary vision transformer (ViT) support
    - Cross-architecture knowledge distillation
    - Custom ASIC/FPGA deployment targets
    - AutoML for ternary architecture search

2b. Technology Upgrade Paths:

  PyTorch 2.x → 3.x:
    Assessment: Monitor PyTorch roadmap
    Compatibility: torch.compile API may change
    Migration: Update when 3.x reaches stable release
    Risk: LOW (PyTorch maintains backward compatibility)

  YOLO Architecture Evolution:
    Assessment: ultralytics releases new YOLO versions frequently
    Compatibility: ResiBit blocks are architecture-agnostic
    Migration: Swap backbone, retrain, validate metrics
    Risk: LOW (modular block design)

  ARM Architecture (NEON → SVE):
    Assessment: ARM SVE available on newer cores (ARMv9)
    Compatibility: SVE provides wider vector operations
    Migration: Write SVE kernel variants alongside NEON
    Risk: MEDIUM (hardware not widely available yet)

2c. Architecture Evolution Strategy:

  Short-term (6 months):
    - Stabilise ResiBit-YOLO architecture
    - Publish reproducible results
    - Build community around open-source release

  Medium-term (1 year):
    - Generalize to non-YOLO architectures
    - Explore learned quantization (mixed precision per layer)
    - Investigate knowledge distillation from FP32 teachers

  Long-term (2+ years):
    - Ternary-native architectures (designed for {-1,0,+1} from scratch)
    - Integration with neuromorphic computing paradigms
    - Standardisation of ternary inference formats

3c. Incident Response Playbook:

  Incident: Training diverges (loss → NaN)
    Severity: P2 (blocks progress, not production)
    Response:
      1. Check gradient norms in wandb dashboard
      2. Identify diverging layer (per-layer gradient analysis)
      3. Apply fix: gradient clipping, reduce LR, increase warmup
      4. Post-mortem: Document root cause and update configs

  Incident: Edge inference crash on Pi 5
    Severity: P1 (production, if deployed)
    Response:
      1. Check systemd logs: journalctl -u resibit-yolo
      2. Check memory: free -m (OOM kill?)
      3. Check temperature: vcgencmd measure_temp (throttling?)
      4. Restart service, monitor for recurrence
      5. Post-mortem: Document and add monitoring for root cause

  Incident: COCO evaluation metrics drop after code change
    Severity: P2 (regression)
    Response:
      1. Identify commit that introduced regression (git bisect)
      2. Compare wandb runs: before vs after
      3. Revert commit if fix is not obvious
      4. Post-mortem: Add regression test to prevent recurrence
