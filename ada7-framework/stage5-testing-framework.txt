4. FAILURE RESPONSE PROTOCOL
------------------------------------------------------------------------

4a. Training Failure: mAP Does Not Improve

  Root Cause Analysis:
    Step 1: Check gradient norms (detect Muon Trap / gradient explosion)
    Step 2: Check weight distributions (detect dead-zero collapse)
    Step 3: Check loss components (detection vs spectral orthogonality)
    Step 4: Compare with FP32 baseline training dynamics

  Decision Framework:
    IF gradient_norm > 100: Quick fix → reduce learning rate
    IF dead_zero_pct > 50%: Quick fix → increase INT8 highway width
    IF loss_nan: Quick fix → add gradient clipping
    IF none_of_above: Sustainable fix → review architecture design

  Rollback Procedure:
    1. Load last successful checkpoint
    2. Reduce learning rate by 10×
    3. Increase warmup epochs by 2×
    4. Re-enable full INT8 highway (Precision Funnel = 1.0)

4b. Deployment Failure: Inference Accuracy Mismatch

  Root Cause Analysis:
    Step 1: Compare PyTorch vs ONNX output (max absolute difference)
    Step 2: Check quantization rounding (ternary weights match)
    Step 3: Verify Base-5 fusion arithmetic

  Rollback Procedure:
    1. Skip Base-5 fusion, deploy dual-stream model
    2. Fall back to INT8 quantization if ternary deployment fails
    3. Report accuracy gap with detailed layer-by-layer analysis

4c. Performance Failure: Below Throughput Target

  Root Cause Analysis:
    Step 1: Profile inference (identify bottleneck layers)
    Step 2: Check memory bandwidth utilisation
    Step 3: Verify ARM NEON kernel is being used (not fallback)

  Mitigation:
    1. Reduce model width (fewer channels)
    2. Reduce input resolution (640 → 416 → 320)
    3. Enable TFLite XNNPACK delegate for optimised inference
